# Staged methods in ThinkTUI

Choose a project → Method Library (Ctrl+P) → search → choose a method → name your analysis. Matrix, ACH, AHP, Forecast Journal and Scenarios open **guided forms** (F8 validates/saves each step, F7 back, F6 advanced JSON) by default. These forms keep missing judgments blank and save after each completed step. Other staged methods use an **editable JSON worksheet**. An illustrative example appears in a worksheet but is **not saved** until you replace it with your own data, validate, and select **Validate · Calculate · Save**. The results are calculated locally in Python, autosaved at validation, resumed with the session, and included in Markdown/JSON exports. Bad inputs do not replace the last valid saved state. AI is never used for arithmetic. Common analysis fields (problem, objective, what would change your mind) are independent of the worksheet.

## Weighted Decision Matrix guided input

Use **Add option** to name at least two alternatives (including doing nothing if relevant). On the next step, use **Add criterion** to enter each criterion's name and your own nonnegative relative weight; explicitly choose **Benefit** when a higher score is better or **Cost** when a lower score is better. At least one weight must be positive; weights need not add to 100 because calculation normalizes them. Enter your own 0–10 scores in the option-by-criterion grid (higher on a cost criterion means *more* cost). The grid scrolls horizontally when needed; Tab moves between cells. The optional bulk editor still accepts one option per line or `Name | weight | benefit or cost` per line; editing it replaces the row editor contents at the next validation. F8 validates and saves each step; incomplete/invalid rows are not saved. When revisiting a scored matrix, changes to option or criterion labels require explicit mapping of old scores; cancelling keeps the saved judgments.

On a valid matrix's **Review** step, choose any two distinct scored options (the top two ranked options are preselected) and press **Test sensitivity of two options** when there are at least two criteria. The linked draft copies only those two options and their existing judgments without editing the matrix; the Sensitivity form lets you edit 0–10 scores (including decimals), the varied criterion and the lower/upper weight bounds as decimals from 0 to 1 (e.g. 0.25–0.75). The lower bound must be less than the upper bound. Bounds entered in a new, unlinked analysis remain blank until you supply them. An optional Advanced JSON view is still available but not required.

AHP criteria/alternatives, ACH hypotheses and Scenario Planning driving forces remain **one name per line**: they are plain labels with no inline weights, directions or other syntax to parse. This keeps keyboard entry and bulk paste straightforward. Their guided steps state the required counts; duplicates are rejected on validation. Unlike matrix criteria, no numeric judgment can be lost when a label is reopened.

## Decision & problem methods (V0.2 plus AHP)

| Method | Required worksheet fields | Interpretation / limits |
| --- | --- | --- |
| Analysis of Competing Hypotheses | `hypotheses` names, `evidence` with `title`, optional `source`/provenance, `reliability` 0–1 and `ratings` per hypothesis (`++`, `+`, `0`, `-`, `--`, `?`) | Evidence diagnosticity is max minus min known rating; inconsistency sums reliability × diagnosticity × contradiction magnitude. Lower is less contradicted; not a Bayesian posterior. `?` is not negative evidence. |
| Expected Value | `alternatives` with `name`, `outcomes` containing `probability` 0–1 and numeric `value` | Each alternative's probabilities must sum to one; all values must use the same unit. No probabilities are provided by AI. |
| Decision Tree | `tree` with `type`: `outcome` + `value`; or `chance` / `decision` with named `branches`, each pointing to a nested `node`; chance branches also have `probability` | Chance probabilities sum to one. Decisions display the highest **expected-value** branch as a mathematical result, not a user decision. Depth limited to 50. |
| Sensitivity Analysis | `criteria` with names, nonnegative `weight` and optional `direction` (`benefit`/`cost`); exactly two `alternatives` with 0–10 `scores`; `vary` criterion name and `range` in 0–1 | Varies one criterion's normalized weight, rescales others proportionally, calculates the exact crossing (if one falls in range). A validated Decision Matrix with at least two alternatives can start a linked sensitivity snapshot of the chosen pair via **Test sensitivity of two options**; changes to the source later do not automatically propagate. Not a general nonlinear parameter analyzer. |
| Analytic Hierarchy Process | `criteria` and `alternatives` names, square reciprocal `criteria_matrix`, `alternative_matrices` for each criterion | Positive reciprocal judgments, principal priority vectors via power iteration, CI and Saaty CR for sizes 1–10. Review CR above 0.1; CR is not a guarantee of correct priorities. |

## Forecasting (V0.3)

| Method | Required worksheet fields | Interpretation / limits |
| --- | --- | --- |
| Probability Forecast Journal | `forecasts`: question, probability 0–1, `outcome`: 0/1 or null; optional resolution date/rationale | Brier score is mean `(p - outcome)²` for resolved questions only. Calibration bins summarize predicted/observed frequencies; small bins should not be overinterpreted. |
| Reference-Class Forecasting | `cases`: user-entered historical estimate and actual (>0 estimate), `inside_estimate` | Mean/median and interpolated p10/p90 of actual/estimated ratios; projected outside-view estimate = inside estimate × ratio. Estimates and actuals accept fractional values. Reference-class comparability is a human judgment. No fabricated observations. |
| Monte Carlo Simulation | `variables` with unique names, `distribution`, parameters, optional linear `coefficient`; `constant`, `threshold`, `seed`, `iterations` | Supported: `uniform` (`min`,`max`), `triangular` (`min`,`mode`,`max`), `normal`/`lognormal` (`mean`,`sd`; lognormal parameters are on the **log scale**), `discrete` (`values`,`weights`), `samples` (`values`). Simulates `constant + Σ(coefficient × draw)` with a fixed seed (100–50,000 iterations), reports mean, p10/p50/p90 and probability > threshold. Distribution parameters, coefficients, constant and threshold accept decimals; seed and iterations require whole numbers. Units and model structure are user-defined; no arbitrary Python expressions are evaluated. Runs in a background thread in the TUI. |

## Strategy, risk & systems (V0.4)

| Method | Required worksheet fields | Interpretation / limits |
| --- | --- | --- |
| Scenario Planning | `question`, two named `axes` with `low`/`high` poles, four `scenarios` keyed `low_low`, `low_high`, `high_low`, `high_high` with user-written name/narrative and optional implications/indicators | Four structurally checked quadrants and a `strategies` list with a named action in every quadrant; narratives and strategies are user supplied, not generated or assigned probabilities. |
| Backcasting | `future_state`, ISO `target_date`, dated `milestones` with requirements | Sorts milestones backward from target; dependencies and feasibility need human review. |
| Objectives Hierarchy | parent-linked `nodes` with `id`, `parent_id`, label, `kind` fundamental/means | Nested hierarchy with kinds; currently JSON worksheet, not the Issue Tree keyboard editor. |
| Value-Focused Thinking | `objectives` with name, fundamental/means `kind`, `measure`; optional `alternatives` | Structures objectives and alternatives, not a scoring calculation. |
| FMEA | `failure_modes` with mode, effect, cause, controls, severity, occurrence, detectability, action and owner; optional `scale_max` 2–20 (default 10) | Shows dimensions and an RPN = S×O×D as **screening only**. Do not compare RPN across teams with incompatible scales or ignore high-severity low-frequency modes. |
| Theory of Constraints | `goal`, `constraint`, `evidence`, `exploit`, `subordinate`, `elevate`, `reassess` | Explicit bottleneck hypothesis and follow-up plan; no unearned throughput claim. |

**Current UX limits:** guided ACH records evidence one item at a time with explicit ratings for every hypothesis; AHP asks for individual ratios and reports consistency; Forecast Journal supports unresolved/resolved records without scheduled reminders; Scenario Planning walks through four quadrants and strategies without generating narrative. Guided forms are not graphical matrices or charts. Simulation charts and guided interfaces for the other worksheet methods remain future UX work. The additional 20 catalog methods are implemented as validated JSON worksheets; see [the catalog guide](catalog.md). The library lists runnable methods, but a worksheet is not the same as a guided screen.
