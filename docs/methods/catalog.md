# Additional catalog methods — worksheet guide

All 40 methods appear in the searchable library. The additional catalog methods open in schema-driven forms (31 methods currently have forms); F6 opens an optional Advanced JSON editor. New worksheets start blank. **Load example** is optional, and unchanged illustrative inputs cannot be marked complete. Enter your own judgments and choose **Save & calculate**. Invalid inputs leave prior completed results intact. Resume, history, Markdown decision brief and JSON export use the saved worksheet. This is **not** a dedicated step-by-step guided screen for every method. For numeric methods, the local Python result is authoritative; for qualitative methods the output is a structure, not an invented score. AI suggestions cannot become facts without approval.

| Method | Required data / computation | Caveat |
| --- | --- | --- |
| Bradley–Terry Ranking | `items` names; `comparisons` `{a,b,outcome}` where outcome is `a_wins`, `b_wins` or `tie`; estimates relative strengths using PairRank's tested engine. | For complete scheduled, randomized pair judgments, use **Pairwise Ranking** instead. Strength score is not a probability. |
| Value of Information | `states` probabilities summing to 1; `actions` payoffs per state; `signals` with P(signal|state) summing to 1 over signals for each state; `research_cost`. Computes EVPI and EVSI. | Signals' accuracy and state prior are user-supplied. No information is generated from an LLM. |
| Opportunity Cost | `chosen`, named `alternatives` with comparable numeric `value`; reports best forgone value and gap. | A negative gap means the chosen option already exceeds the best forgone alternative. |
| Reversibility Analysis | alternatives with `rollback_cost`, `rollback_days`, `trigger`, `exit_plan`. | Dimensions are shown separately; no fake universal reversibility score. |
| Hypothesis Tree | `question`, parent-linked `nodes` with `id`, `parent_id`, `label`, `kind` (`hypothesis`/`test`); tests may carry an optional `result` (`Untested`/`Supports`/`Contradicts`/`Inconclusive`, blank = untested). | Schema form and optional Advanced JSON, not the interactive Issue Tree widget. Hypotheses are not findings. The result counts each hypothesis's test outcomes and lists untested tests; it never declares a hypothesis true or false. A result left on a node changed to a hypothesis is kept but not counted. |
| Assumption Mapping | assumptions with `statement`, optional `basis`, confidence 0–1, impact if wrong 1–10, `test`, optional per-assumption `change_mind` (labelled **Disproved if…**) and `status` (labelled **Test result**: Untested = not yet tested, Supported = held, Weak = mixed, Falsified = disproved; blank = Untested); ranks `(1-confidence)×impact` and labels each TEST FIRST / Important / Monitor / Watch (confidence < 0.5 is low, impact ≥ 6 is high). A `review` summary counts tested assumptions and lists disproved ones and untested TEST FIRST ones. | Quadrants and ranks are screening heuristics. |
| Root Cause Analysis | `problem` (the specific failure being explained, narrower than the planning question), candidate `causes` with `claim`, `supporting`/`contradicting` evidence arrays and a `test`. | Recording a candidate never establishes causality. |
| Five Whys | `problem` (the specific failure being explained), 1–5 `chain` items `{why,answer}`, and `root_test`. | Causal links need validation; interactions may not form a simple chain. |
| Fishbone / Ishikawa | `effect`, categories with lists of candidate causes. | Groups ideas; does not assert causal proof. |
| Evidence Matrix | `hypotheses`, evidence entries `{title,source,reliability,ratings}` with `+`, `-`, `0`, `?` for every hypothesis. | Contradictions are explicit; no Bayesian posterior or fabricated diagnosticity. |
| Risk Matrix | `scale_max` 2–10, risks with ordinal `likelihood`, `impact`, `mitigation`, optional `owner`; outputs both dimensions and product. | Ordinal product is **not a calibrated probability**. |
| Fault Tree Analysis | nested `AND`/`OR` gates with `independent:true`, two or more children, basic `event` leaves with `probability` 0–1. | Repeated basic-event names refer to the *same* event and must have identical probabilities; distinct basic events still assume independence (shared causes are not modeled). 40-level, 300-event and 50,000-logic-node limits. |
| Bow-Tie Analysis | `hazard`, `top_event`, `threats` with preventive controls and `consequences` with mitigating controls; each may list optional `escalation_factors` (conditions that could make its controls fail). | Does not claim controls are effective until checked. Threats and consequences without escalation factors are listed as not yet challenged. |
| Fermi Estimation | `operation` `sum` or `product`, nonnegative factors with `low`, `estimate`, `high`. | Factor bounds and estimates accept decimals. Extremes are scenarios, **not confidence intervals**. |
| Bayesian Updating | `hypothesis`, `prior`, evidence with `p_if_true` and `p_if_false`; sequential Bayes updates. | Avoid double-counting dependent evidence; likelihood estimates come from the user. |
| Indicators & Signposts | `indicators` with scenario name, threshold, `direction` (`above`/`below`), optional `current`, and action. | Thresholds and readings accept decimals. A trigger is a prompt to investigate, not a prediction. |
| Strategy Stress Test | `scenarios`, `strategies` with score 0–10 **for every scenario**; ranks by minimum score. | User judgments; no invented scenario probabilities or weighted average. |
| Causal Loop Analysis | unique `variables`; signed `links` with `from`, `to`, `polarity` +1/-1. | Finds qualitative reinforcing/balancing cycles, not trajectories; 50 variables/300 links, first 100 loops up to 12 links. |
| Bottleneck Analysis | serial stages with positive `capacity`, optional proposal with replacement capacity. | Minimum capacity is a simplified steady-state bound; ignores variability, queues and parallel routing. |
| Stock-and-Flow Model | stocks with nonnegative initial level, named flows with `from`/`to` stock or null (external) and nonnegative constant `rate`, `dt` positive. | **One simultaneous step**, not dynamic feedback; rejects steps producing negative stocks. |

## Cross-method planning

Use **Help me choose** on Home to select a goal and see transparent rule-based recommendations. Open a project first or create one after selecting a method. From a running analysis, **Recommended next method** suggests a next step; choosing one explicitly creates a linked draft. Only already user-entered problem/objective and selected labels are copied. For example, Premortem → FMEA copies a failure name and preventive action, **not** severity/occurrence/detectability, so the user must supply those before calculation. Objectives → Matrix copies fundamental objective names, **not** weights; Matrix → Sensitivity copies the user's criteria and scores as a one-time snapshot. Scenario Planning → Strategy Stress Test copies scenario and strategy names, **not** performance scores. The prior record is never modified by the handoff, and changes to it do not silently propagate. For **sequential, linked workflows**, open a project → **Plan workflow**, choose a goal, enter a problem statement and select **Start linked, step-by-step workflow**. This creates only the first draft. Review and finish each analysis, then choose **Continue planned workflow** and explicitly confirm the suggested next method. The project list shows stage progress. The Matrix → AHP handoff copies only criterion and alternative names, never matrix scores as AHP judgments. A linked plan stores its step order and source IDs in the session so it survives restart and snapshot import; links are not live synchronization and no stage runs automatically. Other recommendations remain optional, independent one-step handoffs. Most of the catalog still has worksheets, not guided screens.
